## 1. 背景与目标

### 1.1 背景

WebProtégé 是斯坦福 Protégé 团队维护的在线本体协作编辑器。当前代码库的界面语言机制基于 GWT i18n，官方仅注册了 4 种语言：

- `en`（默认，回退语言）
- `de`（已声明，但仓库内**无翻译文件**，实际仍显示英文）
- `sl`（斯洛文尼亚语，`Messages_sl.properties`，156 行，部分翻译）
- `pt`（葡萄牙语，`Messages_pt.properties`，188 行，部分翻译）

**没有任何中文语言包**，因此本设计要解决的核心问题是：在不破坏上游代码结构、可随上游升级持续维护的前提下，为 WebProtégé 建立完整的简体中文本地化能力。

### 1.2 目标

1. **P0（必须）**：客户端主界面框架文案全部汉化——即 `Messages` 接口（287 条默认消息）与 `FormsMessages` 接口（42 条）共 **329 条词条**提供中文翻译，通过 GWT locale `zh_CN` / `zh` 激活。
2. **P1（必须）**：客户端散落的硬编码英文 UI 文案改造为走 i18n 通道并翻译（甄别后预计 80~120 条）。
3. **P2（可选）**：服务端高频用户可见文案（未登录、权限不足等错误提示）支持中文。
4. **P3（可选）**：系统邮件、服务端渲染 JSP 页面支持中文。
5. 中文浏览器**无需任何操作自动进入中文界面**（依赖现有 Accept-Language 协商机制）；`?locale=en` 可强制切回英文。
6. 建立词条提取 / 翻译 / 回填 / 校验的工程化流水线与术语表，保证翻译一致性并支持上游版本升级后的持续同步。

### 1.3 非目标（明确不做）

| 事项 | 理由 |
|---|---|
| 本体**内容数据**的翻译：实体标签（`rdfs:label`）、注释、项目名、表单字段标签（LanguageMap 数据）、标签名、评论内容 | 这些是用户数据，不是界面文案。且系统本身支持数据级多语言（见 4.8），中文标注由用户自行维护 |
| 第三方 GWT 库（widgetmap / graphtree / codemirror-gwt）内部文案汉化 | 均为外部 jar，无 i18n 通道，fork 成本高、影响面极小（见 4.7） |
| `About` 弹窗版本信息（`VersionInfo.properties`）、日志文案、API/Action 类名、权限 ActionId | 非面向最终用户的界面文案 |
| 繁体中文（zh_TW）、其他变体 | 本期仅做 zh / zh_CN，机制建立后可平滑扩展 |

## 2. 系统现状深度分析

### 2.1 总体架构

```
┌─────────────────────────── 浏览器 ───────────────────────────┐
│  GWT 编译产物 (webprotege.nocache.js +-permutation)           │
│  Messages_zh 实现 = 编译期由 Messages_zh.properties 生成      │
└──────────────┬───────────────────────────────────────────────┘
               │ HTTP / GWT RPC
┌──────────────▼───────────────────────────────────────────────┐
│ webprotege-server (war)                                      │
│   ├ WebProtege.jsp      ← 宿主页，注入 locale 元信息          │
│   ├ GWT RPC Servlets    ← 异常 message 直传客户端弹窗显示      │
│   ├ Mailer（JavaMail）   ← 邮件正文硬编码英文                  │
│   └ MongoDB / Lucene    ← 业务数据与检索                      │
└──────────────────────────────────────────────────────────────┘
```

Maven 模块（8 个）：`webprotege-client`（GWT 客户端，**gwt-maven-plugin 在此模块执行编译**）、`webprotege-server`（war 装配）、`webprotege-server-core`、`webprotege-server-api`、`webprotege-server-lucene`、`webprotege-shared`、`webprotege-shared-core`（GWT 库模块，源码透传给客户端编译）、`webprotege-cli`。

客户端 Java 源文件共 **1331 个**；第三方 GWT 依赖：`widgetmap 4.0.1`（布局编辑器）、`graphtree 1.1.1`（项目树）、`codemirror-gwt 3.0.0`（代码高亮编辑器）、`gwt-elemental 2.8.2`。

### 2.3 现有 i18n 机制剖析

1. **GWT 模块声明**（`webprotege-client/src/main/module.gwt.xml`）：
   ```xml
   <set-property-fallback name="locale" value="en"/>
   <extend-property name="locale" values="en"/>
   <extend-property name="locale" values="de"/>
   <extend-property name="locale" values="sl"/>
   <extend-property name="locale" values="pt"/>
   ```
   GWT 按声明的 locale 生成每语言一份编译产物（permutation）；运行期取不到的 key 回退到 `@DefaultMessage` 英文默认值——**这意味着翻译文件可以渐进补齐，缺一条只会该条显示英文，不会崩**。

2. **locale 自动协商（关键发现）**：宿主页 `webprotege-server/src/main/webapp/WebProtege.jsp` 中已有：
   ```jsp
   <meta name="gwt:property" content="locale=<%= request.getLocale() %>">
   ```
   `request.getLocale()` 由 Servlet 容器从浏览器 `Accept-Language` 头解析。即：**只要在 module.gwt.xml 注册 `zh` / `zh_CN`，中文浏览器访问站点就会自动进入中文界面，无需新增语言切换 UI**。GWT locale 解析优先级（以 GWT 2.8.2 I18N 模块 property-provider 为准）：URL 查询参数 `?locale=xx` ＞ 宿主页 meta ＞ 默认回退值。**首次联调时需用冒烟用例验证该顺序**（见 6.2）。

3. **翻译文件加载与回退链**：GWT 编译期将 `Messages_zh_CN.properties` → `Messages_zh.properties` → `@DefaultMessage` 逐级回退（父 locale 继承）。因此只需维护一份 `Messages_zh.properties`，同时注册 `zh` 和 `zh_CN` 两个 locale 值即可同时覆盖"中文"与"简体中文"两种 Accept-Language。

4. **编码格式实例证据**：现有 `Messages_pt.properties` 为**原生 UTF-8**（含 `sessão` 等非 ASCII 字符直接存储），官方线上 Portuguese 界面正常显示，证明本工程 GWT i18n rebind 按 UTF-8 读取 properties。**中文词条可直接以 UTF-8 书写，无需 `\uXXXX` 转义**（备选转义方案见 3.3 风险处置）。

5. **界面语言与数据语言的联动**：`client/form/LanguageMapCurrentLocaleMapper.java` 用 `LocaleInfo.getCurrentLocale().getLocaleName()` 获取当前 locale 去匹配表单标签 `LanguageMap`——界面切到 `zh_CN` 后，表单标签、语言过滤器会自动优先取 `zh_CN` 标注的数据标签，与本汉化方案天然协同。

6. **客户端取词通道**：客户端通过 Dagger 注入 `Messages`/`FormsMessages` 实例取词（全客户端识别到 `MESSAGES.xxx()`/`messages.xxx()` 等调用点 189 处、覆盖 62 个文件）。但 1331 个文件中仍有约 183 处散落英文句式字面量（见 2.2-E），说明历史改造不彻底，这正是 P1 的工作对象。

7. **权限/角色体系**：`webprotege-shared-core/.../access/BuiltInAction.java`、`BuiltInRole.java` 为内部 ID 枚举；分享设置等 UI 文案已走 `sharing.*` 词条（11 条），无需单独处理。

### 2.4 构建与部署链路

- GWT 编译发生在 `webprotege-client` 模块（根 `pom.xml` 中 pluginManagement 管理 gwt-maven-plugin）。每新增一个 locale，GWT 多编译一个 permutation，**客户端编译时间约增加 1/N（N 为 permutation 总数，当前受 `user.agent=gecko1_8,safari` 收敛后约 5 个，注册 zh+zh_CN 后约 7 个）**，浏览器端每用户只需下载自己 locale 的那份产物，体积不受影响。
- 本环境构建备忘（来自既有实践）：Maven 需用 `.mvn/settings.xml`（其中镜像掉 `stanford/oss-sonatype` 仓库）；`docker build` 需加 `--network=host`；本机跑过 mongod 时注意残留进程占端口。

### 2.5 现状结论

1. WebProtégé 的 i18n **骨架完整、覆盖不全**：框架文案（329 条）走标准 GWT i18n 通道，补一份中文 properties 即可获得约 70% 的界面汉化，风险低。
2. 剩余缺口集中在：少量 UiBinder 字面文本、散落 Java 硬编码（P1），以及服务端文案/邮件（P2/P3，可分期）。
3. 宿主页已具备 Accept-Language 自动协商，**注册 locale 即自动生效**，无需开发语言切换器。
4. UTF-8 properties 在本工程已被验证可行，中文无需转义处理。
5. 数据级多语言与界面 locale 联动是现成能力，汉化后中文用户可无缝使用中文标注的表单/实体标签。

## 3. 总体方案设计

### 3.1 分层分级策略

| 层级 | 范围 | 实现手段 | 优先级 |
|---|---|---|---|
| L1 | 客户端框架文案（A/B 类，329 条） | 新增 2 个 properties 文件 + module 声明 | **P0** |
| L2 | 客户端硬编码（D/E 类） | 代码改造：UiBinder 字面文本移入 Messages；散落字面量注入 Messages | **P1** |
| L3 | 服务端高频错误文案（F 类） | 服务端 MessageCatalog + locale 传播 | P2（可选） |
| L4 | 邮件（G 类） | 模板化 + 按 locale 选模板 | P3（可选） |
| L5 | JSP 页面（H 类） | 直接汉化/双语 | P3（可选） |
| — | 第三方库、数据内容 | 不汉化（决策见 4.7 / 1.3） | — |

### 3.2 Locale 注册与激活机制

**module.gwt.xml 修改（增量 diff）：**

```xml
<!-- 简体中文：注册 zh 与 zh_CN 两个 locale 值，
     运行期 zh_CN 未命中的 key 自动继承 Messages_zh.properties，
     再未命中回退 @DefaultMessage（英文），因此只需维护一份 Messages_zh.properties -->
<extend-property name="locale" values="zh"/>
<extend-property name="locale" values="zh_CN"/>
```

`set-property-fallback` 保持 `en` 不变。

**激活路径（三选一，默认走 ①）：**

1. **自动协商（零改造）**：利用 `WebProtege.jsp` 现有 `<meta name="gwt:property" content="locale=<%= request.getLocale() %>">`。浏览器语言为 `zh-CN`/`zh` 的用户自动进入中文界面。
2. **整站强制中文（私有化部署常用）**：将 JSP 中该 meta 行硬编码为 `content="locale=zh_CN"`；或在 `webprotege.properties` 增加部署配置项 `application.locale=zh_CN` 由 JSP 读取（推荐，保留灵活性）。此项作为可配置开关设计：
   ```jsp
   <%-- 读取 webprotege.properties 中 application.locale，未配置时保持 Accept-Language 协商 --%>
   <meta name="gwt:property" content="locale=<%= appLocaleOrRequestLocale(application) %>">
   ```
3. **用户手动切换**：URL 带 `?locale=en` / `?locale=zh_CN` 临时切换（GWT 原生支持，验证优先级后可作为文档化用法）。不新增界面语言选择器（如后续需要，可在用户设置页加下拉框，取值 `LocaleInfo.getAvailableLocaleNames()` 并持久化到用户配置，本期不实现）。

### 3.3 资源文件设计

**新增文件（目录与现有 pt/sl 完全一致）：**

```
webprotege-client/src/main/resources/edu/stanford/bmir/protege/web/client/
├── Messages_zh.properties          ← 新增，P0
├── FormsMessages_zh.properties     ← 新增，P0
├── Messages_pt.properties          （既有，参照）
└── Messages_sl.properties          （既有，参照）
```

**文件格式规范：**

1. 编码：**原生 UTF-8，不转义**（跟随仓库既有 pt/sl 惯例，见 2.3-4）。
2. key：与 `Messages.java` 中 `@Key("…")` **逐字一致**（多数为点分小写，如 `change.downloadRevision`；部分为 camelCase，如 `create`——不改 key，保持原样）。
3. 条目顺序：按 `Messages.java` 中的声明顺序排列，便于与源文件对照 diff。
4. 注释：文件头加一段说明（范围、维护约定、回填脚本用法），按 `@Key` 前缀域加分节注释（`# project.*` 等）。
5. 换行/空白：值内不要引入首尾空格；原文中的双空格（如 `"Loading project.  Please wait."`）中文合并为单空格。

**转义备选方案**：若某版本 GWT 升级后出现乱码（2.3-4 的结论被推翻），执行 `native2ascii -encoding UTF-8 Messages_zh.properties.tmp > Messages_zh.properties` 转为 `\uXXXX` 存储——该转换对 GWT 透明，作为应急预案保留。

**SafeHtml 说明**：`Messages` 接口中部分方法返回 `SafeHtml`，properties 条目对它们同样按纯文本 key=值 提供（GWT 生成器负责转义），无需特殊格式。

### 3.4 翻译规范

1. **占位符**：`{0}`、`{1}` 等必须原样保留；中文语序允许重排（如 `"{0} was deleted"` → `"{0} 已被删除"`），GWT MessageFormat 按编号取参，与位置无关。
2. **标点**：中文语境使用全角标点；但含占位符、IRI、路径、快捷键说明的句子中保持半角，避免复制可用性受损。省略号用 `…`。
3. **长度控制**：按钮/标签类词条 ≤ 6 个汉字为宜（中文普遍短于英文，布局风险低）；对话框标题 ≤ 20 字。
4. **专有名词不译**：WebProtégé、OWL、OWL API、IRI、IRI 前缀名、CodeMirror、MongoDB 等。
5. **风格**：面向最终用户的界面用语，简体，"你"（不用"您"与"您"混杂）；按钮用动词短语（"新建项目"而非"项目的创建"）；错误消息给出可行动的下一步。
6. **一致性**：同一英文术语全库同一译法，以 3.5 术语表为准；`@AlternateMessage`（2 条）与上下文相关的词条须结合使用场景翻译，逐条人工审校。
7. **禁止翻译项**：邮件地址样例、代码片段、`{0}`、HTML 标签、`@Key` 本身。

## 4. 详细设计

### 4.1 P0：客户端框架词条汉化（329 条）

**流水线：提取 → 翻译 → 回填 → 校验 → 编译验证。**

1. **提取**：运行附录 B-1 脚本，从 `Messages.java` / `FormsMessages.java` 生成制表符分隔的工作簿底稿 `docs/hanhua/messages-template.tsv`（列：key、英文默认值、领域前缀、中文译文留空）。`@AlternateMessage` 的 2 条在脚本中标记 `MANUAL`，人工处理。
2. **翻译**：在 TSV 中完成中文列（建议导入表格软件按 3.5 术语表协作翻译 + 一人审校）。
3. **回填**：运行附录 B-2 脚本把 TSV 回填为 UTF-8 `Messages_zh.properties` / `FormsMessages_zh.properties`（按源声明顺序、加分节注释）。
4. **校验**：运行附录 B-3 脚本做 parity 与占位符校验（见 6.1），作为后续 CI 门禁。
5. **编译验证**：注册 locale（3.2）后执行构建，确认 permutation 生成并部署冒烟。

**产出物**：2 个 properties 文件、1 份 TSV 工作簿、3 个脚本。

### 4.2 P1：客户端硬编码改造

**工作方法**：不是逐文件人肉搜索，而是按 2.2-E 的 grep 命令生成候选清单（保留到 `docs/hanhua/hardcode-inventory.md`），逐条甄别"UI 可见文案 / 日志 / 非文案常量"，仅对 UI 文案改造。

**改造模式 A —— Presenter/View Java 硬编码（约 10 处 setter + 1 处 busy 提示等）：**

```java
// 改造前：webprotege-client/.../client/project/ProjectPresenter.java:90
busyView.setMessage("Loading project.  Please wait.");

// 改造后：
busyView.setMessage(messages.project_loading());
```

同时在 `Messages.java` 尾部按既有风格追加：

```java
@DefaultMessage("Loading project. Please wait.")
@Key("project.loading")
String project_loading();
```

（类内已有 `Messages messages` 注入；无注入的类按既有 Dagger 构造器注入模式补齐。）

**改造模式 B —— UiBinder 字面文本（3 个文件）：** 优先将文本移入 Presenter 代码经 `Messages` 设置（改动最小、不引入 UiBinder Messages 生成文件）；若该 View 无对应 Presenter 逻辑，则采用 GWT UiBinder 原生 `ui:msg` 机制：

```xml
<ui:messages generate="com.example.webprotege.client.ChgPwdMessages"/>
<g:Button><ui:msg>Change password</ui:msg></g:Button>
```

并在 `module.gwt.xml` 注册生成器产物对应的翻译文件。**本设计推荐前者（移入 Messages）**，保持全项目单一翻译通道。

**改造模式 C —— `.setText("…")` 57 处：** 甄别规则：参数为英文句式字面量 → 改造；参数为实体名/动态拼接 → 跳过。

**回归点**：P1 触碰 62~100 个 Java 文件，属结构性改动，要求：每改造一个包跑一次 `mvn -pl webprotege-client -am compile` 快速编译验证；改造项逐条记入清单并标注完成状态；此层改动**独立成 commit 序列**（与 P0 的资源文件分离），便于上游同步与回滚。

### 4.3 P2（可选）：服务端高频文案汉化

**现状**：服务端异常消息直接经 GWT RPC 异常通道传到客户端 `MessageBoxErrorDisplay` 弹窗（见 `webprotege-client/.../client/dispatch/MessageBoxErrorDisplay.java`），文案硬编码于 server-core 各 handler。

**设计**：
1. 新增 `webprotege-server-core/src/main/resources/messages_zh.properties`（及默认 `messages.properties`），建立 `ServerMessages` 工具类（`ResourceBundle` 封装，按 key 取词，缺 key 回退默认英文）。
2. **locale 传播**：GWT RPC 请求为普通 HTTP POST，容器可从 `Accept-Language` 解析 `request.getLocale()`。新增一个作用于 RPC servlet 的过滤器/基类工具：将解析出的 locale 放入请求上下文（`ThreadLocal` 或 `request attribute`），handler 内取词时使用。不改变 RPC 接口签名。
3. **范围收敛**（控制改造面）：仅汉化高频四类——未登录/会话过期、权限不足（`AuthorizationRequested*`）、名称冲突/重名校验、上传文件校验错误。其余服务端异常保持英文（技术性文案对中文用户可读性尚可）。

### 4.4 P3（可选）：邮件汉化

现状两类邮件（密码重置、评论通知）正文/主题在 Java 代码拼接（2.2-G）。设计：
1. 抽取为 `mail-templates/<locale>/reset-password.{subject,html}`、`comment-notification.{subject,html}` 模板文件，`{0}` 占位符由现有 `with("pwd", pwd)` 风格参数填充。
2. 收件人语言来源：用户详情无语言字段——**新增 `UserDetails.languageTag`（可选字段）**，或在管理端 webprotege.properties 配置单一 `mail.locale`（简化方案，推荐先做）。默认回退英文模板。
3. 该项涉及 DB 模型或配置项，独立评审后实施。

### 4.5 P3（可选）：JSP 页面汉化

`forbidden.jsp`、`configuration-error.jsp` 为独立错误页，私有化部署场景直接汉化为中文（或按 `request.getHeader("Accept-Language")` 输出中英双语，十几行 JSTL 即可）。不引入额外框架。

### 4.6 字体与布局适配

1. **字体栈**：`webprotege-server/src/main/webapp/css/WebProtege.css` 的全局 font-family 追加 CJK 字体回退：`"PingFang SC", "Microsoft YaHei", "Noto Sans CJK SC", sans-serif`（保持既有首选项不变，仅在栈尾追加）。
2. **布局检查项**：中文文本在按钮、树节点、对话框标题中通常更短，溢出风险低；重点检查等宽场景——层级树节点、`CodeMirror` 区域、前缀声明表格。验收时按 6.2 截图清单逐页核对。
3. **换行**：中文无空格长句在 `overflow: hidden` 容器中可能截断，验收发现问题用 `word-break: break-all` 精确修复到具体容器类，不做全局开启。

### 4.7 第三方 GWT 库处理决策

| 库 | 版本 | 内部英文文案出现处 | 决策 | 理由 |
|---|---|---|---|---|
| widgetmap | 4.0.1 | 布局编辑器（"Split vertical"等右键菜单） | **不汉化** | 管理员级低频操作；外部 jar 无 i18n 通道 |

### 4.8 数据级多语言说明（联动，非范围）

界面 locale 切为 `zh_CN` 后：
- 表单标签 `LanguageMap` 按 `zh_CN → zh → 任意` 匹配（`LanguageMapCurrentLocaleMapper` + `LanguageMap.get` 的回退逻辑）；
- 实体渲染优先显示 `rdfs:label@zh` 标注；
- 语言过滤器默认值跟随界面 locale。

因此**实体/表单的中文显示无需本汉化项目做任何开发**，只需用户用中文标注数据。此项在 README 中说明，管理用户预期。

## 附录 B：工程化脚本

### B-1 词条提取 `extract_messages.py`

```python
#!/usr/bin/env python3
"""从 GWT Messages 接口提取 (key, 英文默认值, 行号, 是否需人工) → TSV 底稿"""
import re, sys

MSG_RE = re.compile(
    r'@DefaultMessage\("((?:[^"\\]|\\.)*)"\)'      # 英文默认值
    r'(?P<extra>.*?)'                               # 其余注解（含 AlternateMessage）
    r'@Key\("([^"]+)"\)',                           # key
    re.S)

def unescape(s):
    return s.encode().decode('unicode_escape')

def extract(path):
    src = open(path, encoding='utf-8').read()
    out = []
    for m in MSG_RE.finditer(src):
        english, extra, key = m.group(1), m.group('extra'), m.group(3)
        lineno = src[:m.start()].count('\n') + 1
        manual = 'MANUAL' if '@AlternateMessage' in extra else ''
        out.append((key, unescape(english), lineno, manual))
    return out

if __name__ == '__main__':
    for path in sys.argv[1:]:
        domain = path.rsplit('/', 1)[-1].replace('.java', '')
        for key, en, lineno, manual in extract(path):
            print(f'{domain}\t{key}\t{en}\t{lineno}\t{manual}')
# 用法: python3 extract_messages.py Messages.java FormsMessages.java > messages-template.tsv
```

### B-2 回填 `import_zh.py`

```python
#!/usr/bin/env python3
"""将翻译好的 TSV（列: domain, key, english, lineno, manual, zh）回填为 properties"""
import sys

def main(tsv, out_properties):
    rows = {}
    with open(tsv, encoding='utf-8') as f:
        for line in f:
            parts = line.rstrip('\n').split('\t')
            if len(parts) >= 6 and parts[5].strip():
                rows.setdefault(parts[0], []).append((parts[1], parts[5]))
    with open(out_properties, 'w', encoding='utf-8') as w:
        w.write('# WebProtégé 简体中文语言包（由 docs/hanhua 流水线维护）\n')
        w.write('# 匹配 Messages_zh.properties；key 与 Messages/FormsMessages @Key 一致\n')
        for domain, pairs in rows.items():
            w.write(f'\n# ==== {domain} ====\n')
            for key, zh in pairs:
                w.write(f'{key}={zh}\n')

if __name__ == '__main__':
    main(sys.argv[1], sys.argv[2])
# 用法: python3 import_zh.py messages-template.tsv Messages_zh.properties
```

### B-3 校验 `check_zh.py`（CI 门禁）

```python
#!/usr/bin/env python3
"""校验 zh properties 与 Messages 接口的 parity、占位符、编码、空值"""
import re, sys, subprocess

MSG_RE = re.compile(r'@DefaultMessage\("((?:[^"\\]|\\.)*)"\).*?@Key\("([^"]+)"\)', re.S)
PH_RE  = re.compile(r'\{\d+\}')

def java_keys(path):
    src = open(path, encoding='utf-8').read()
    return {m.group(2): m.group(1) for m in MSG_RE.finditer(src)}, src

def props_keys(path):
    d = {}
    for line in open(path, encoding='utf-8'):
        line = line.strip()
        if line and not line.startswith('#') and '=' in line:
            k, v = line.split('=', 1)
            d[k.strip()] = v
    return d

fails = []
for jpath, ppath in [(sys.argv[1], sys.argv[2]), (sys.argv[3], sys.argv[4])]:
    jkeys, _ = java_keys(jpath)
    pkeys = props_keys(ppath)
    for k in jkeys:
        if k not in pkeys:
            fails.append(f'[缺译] {k}')
        elif not pkeys[k].strip():
            fails.append(f'[空译] {k}')
        elif set(PH_RE.findall(jkeys[k])) != set(PH_RE.findall(pkeys[k])):
            fails.append(f'[占位符不一致] {k}: 英文={jkeys[k]} 中文={pkeys[k]}')
    for k in pkeys:
        if k not in jkeys:
            print(f'[告警] 多余 key: {k}')
for p in sys.argv[2], sys.argv[4]:
    r = subprocess.run(['iconv', '-f', 'UTF-8', p, '-o', '/dev/null'],
                       capture_output=True)
    if r.returncode != 0:
        fails.append(f'[非 UTF-8] {p}')
print('\n'.join(fails) if fails else 'CHECK OK')
sys.exit(1 if fails else 0)
# 用法: python3 check_zh.py Messages.java Messages_zh.properties FormsMessages.java FormsMessages_zh.properties
```
